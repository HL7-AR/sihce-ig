Structures: Logical Models

These define data models that represent the domain covered by this implementation guide in more business-friendly terms than the underlying FHIR resources.

Modelo Lógico de Persona para SIHCE

Modelo Lógico de Persona para SIHCE con foco en empadronamiento e identificación
Modelo lógico BuscarPersona (FederadorBA)

Solicitud de búsqueda de persona por datos mínimos y respuesta mínima.
Modelo lógico Consentimiento (SIHCE)

Registro de preferencias de privacidad del paciente en SIHCE. Tres etapas de madurez: opt-in/out general, opt-in por hospital, hospital + nivel de privacidad.
Modelo lógico DispensaReceta (SIHCE)

Evento de dispensa notificado a SIHCE por la farmacia. Actualiza el índice (anti-quema) y se propaga al repositorio de origen cuando corresponde.
Modelo lógico DocumentoClinico (SIHCE)

Registro e indexación de un documento clínico emitido por un dominio en SIHCE.
Modelo lógico Epicrisis (SIHCE)

Epicrisis (discharge summary) como caso particular de DocumentoClinico con niveles de madurez 1–3.
Modelo lógico FederarPersona (FederadorBA)

Federación de una persona con identificador local y validación de datos.
Modelo lógico Informe de Laboratorio (SIHCE)

Informe de laboratorio indexado vía DocumentReference; contenido DiagnosticReport en URL del dominio.
Modelo lógico ModificarIDLocalPersona (FederadorBA)

Modificación del identificador local de una persona federada.
Modelo lógico ModificarSDMPersona (FederadorBA)

Actualización del SDM de una persona federada; documento inmutable.
Modelo lógico RecetaIndice (SIHCE)

Metadatos de receta indexados en SIHCE. El contenido clínico (MedicationRequest) permanece en el repositorio de origen (SIGEHOS o prestador) salvo el caso excepcional de repositorio delegado en SIHCE.

Structures: Resource Profiles

These define constraints on FHIR resources for systems conforming to this implementation guide.

Composición epicrisis SIHCE

Documento estructurado de epicrisis (LOINC 18842-5). Nivel 2: secciones obligatorias con text. Nivel 3: secciones codificadas con entry (Condition, MedicationStatement).
Condición clínica epicrisis SIHCE

Diagnóstico codificado en secciones de epicrisis nivel 3 (ICD-10 o SNOMED CT edición Argentina).
Consentimiento de paciente SIHCE

Preferencias de privacidad del paciente en la red SIHCE (FHIR R4). Etapa 1: provision.type permit/deny (opt-in/out general). Etapa 2: provision.provision con actor Organization (hospital). Etapa 3: securityLabel normal o confidential (obligatorio y explícito).
Dispensa de receta SIHCE

Evento de dispensa notificado a SIHCE por la farmacia (aplicativo Opción B). Dispara actualización del índice a estado dispensada y propagación al repositorio de origen.
Informe de laboratorio SIHCE

DiagnosticReport referenciado desde DocumentReference (LOINC 11502-2). Nivel 1: presentedForm PDF. Nivel 2: presentedForm + result con Observation codificadas.
Medicación al alta epicrisis SIHCE

Medicamento declarado en la sección de medicamentos al alta (nivel 3).
Observación de laboratorio SIHCE

Resultado analítico codificado (LOINC) asociado a un informe de laboratorio nivel 2.
Paciente SIHCE (PatientXBA)

Perfil de Patient para interoperabilidad SIHCE vía X-BA (empadronamiento y federación)
Parametros Patch Identifier SIHCE

Estructura de Parameters para la operacion $patch-identifier de SIHCE.
Parametros Update SDM SIHCE

Estructura de Parameters para la operacion $update-sdm de SIHCE.
Receta MedicationRequest SIHCE

Contenido clínico de la receta en el repositorio de origen (SIGEHOS, prestador) o en SIHCE como repositorio delegado (excepción).
Referencia a documento clínico SIHCE

Índice federado de documentos clínicos. En POST el dominio emisor registra metadatos con la URL real en content.attachment.url. En GET (consulta ITI-67) SIHCE devuelve URLs del Proxy Central (/Proxy/Binary/{id}). La descarga (ITI-68) es GET al proxy: SIHCE revalida Consent (MCC) y hace proxy pass sincrónico al custodio.
Índice de receta electrónica SIHCE

Metadatos de receta en el índice SIHCE (CUIR, paciente, efector, estado). El MedicationRequest permanece en el repositorio de origen; SIHCE actúa como broker/proxy salvo repositorio delegado (caso 3/1b).

Terminology: Naming Systems

These define identifier and/or code system identities used by systems conforming to this implementation guide.

NamingSystem CUIL (paciente)

Clave Única de Identificación Laboral (CUIL) del paciente, usada en búsqueda de recetas.
NamingSystem CUIR (código único de receta)

Identificador único de receta electrónica (CUIR) en el ecosistema SIHCE / CPE.
NamingSystem Organization hospital (dominio MSGC, ejemplo)

Patrón de identificación de hospitales dentro de un dominio SIHCE: system = {uri-dominio}/Organization, value = id local del hospital.
NamingSystem URI Hospital Italiano (ejemplo FHIR)

Identificador de dominio de ejemplo usado en instancias de este IG.
NamingSystem URI MSGC GCBA (ejemplo)

Sistema de identificadores de ejemplo para Parameters en este IG.
NamingSystem idPersonaGlobal SIHCE

Identificador maestro de persona asignado por SIHCE tras la federación (idPersonaGlobal).
renaper-dni

This NamingSystem defines the official identification document issued by RENAPER in Argentina, the Documento Nacional de Identidad (DNI).
